# Пояснювальна записка

## Анотація

Кваліфікаційна робота (дипломний проєкт) на здобуття освітньої кваліфікації фаховий молодший бакалавр з інженерії програмного забезпечення на тему: «Розробка вебзастосунку інтернет-магазину ігрових комп'ютерів ApexGaming».

Тема кваліфікаційної роботи (дипломного проєкту) передбачає проєктування та розроблення вебсайту інтернет-магазину за допомогою сучасних технологій веброзробки: React, TypeScript, Vite, Tailwind CSS, FastAPI, SQLAlchemy, PostgreSQL та Docker Compose.

Метою виконання кваліфікаційної роботи (дипломного проєкту) є розроблення вебзастосунку, що дає змогу користувачам переглядати готові ігрові комп'ютери, обирати комплектуючі, формувати індивідуальну ПК-збірку, додавати товари до кошика, реєструватися, авторизуватися та працювати з особистим профілем.

У процесі виконання роботи було проаналізовано предметну область інтернет-магазинів комп'ютерної техніки, визначено функціональні та нефункціональні вимоги, спроєктовано клієнт-серверну архітектуру, реалізовано користувацький інтерфейс, серверне API, базову систему авторизації, підключення до бази даних та конфігурацію локального запуску проєкту.

Загальний обсяг пояснювальної записки містить теоретичну, конструкторську, програмну, експериментальну та економічну частини, висновки, список використаних джерел і додаткові матеріали, що описують структуру, функціональність та результати розроблення вебзастосунку.

Графічна частина проєкту може містити схему клієнт-серверної архітектури, структуру бази даних, схему взаємодії frontend, backend і database, UML-діаграми, а також знімки основних сторінок сайту: головної сторінки, каталогу, сторінки комплектуючих, конструктора ПК, кошика, авторизації та профілю користувача.

Результатом дипломного проєктування є вебзастосунок ApexGaming, який демонструє роботу інтернет-магазину ігрових комп'ютерів, забезпечує взаємодію користувача з інтерфейсом, збереження даних кошика, авторизацію користувачів і обмін даними між клієнтською та серверною частинами.

Ключові слова: вебзастосунок, інтернет-магазин, ігровий комп'ютер, React, TypeScript, FastAPI, PostgreSQL, база даних, інтерфейс, API, авторизація, кошик, конструктор ПК.

## 1. Теоретична частина

У теоретичній частині подано загальну характеристику теми дипломного проєкту, обґрунтовано її актуальність, визначено мету, завдання, об'єкт і предмет дослідження. Цей розділ пояснює, чому розробка вебзастосунку інтернет-магазину ігрових комп'ютерів є доцільною та які задачі має вирішувати створена система.

Розробка вебзастосунку інтернет-магазину ігрових комп'ютерів ApexGaming.

Сучасний ринок комп'ютерної техніки активно розвивається завдяки зростанню попиту на ігрові комп'ютери, робочі станції та комплектуючі для високопродуктивних систем. Користувачам важливо швидко переглядати готові конфігурації, порівнювати характеристики, підбирати компоненти та мати зручний спосіб взаємодії з магазином.

## 2. Конструкторська частина

У конструкторській частині визначено вимоги до майбутньої системи та описано її загальну побудову. На цьому етапі проєктування встановлюється, які функції має виконувати сайт, які обмеження потрібно врахувати та як окремі частини системи взаємодіють між собою.

### 2.1 Функціональні вимоги

У межах роботи система повинна забезпечувати такі можливості:

1. Перегляд головної сторінки з презентацією магазину.
2. Перегляд популярних продуктів і переваг магазину.
3. Перехід до каталогу товарів.
4. Перехід до конструктора ПК.
5. Реєстрація нового користувача.
6. Авторизація користувача через email і пароль.
7. Збереження токена авторизації у браузері.
8. Перегляд сторінки профілю користувача.
9. Оновлення аватара профілю.
10. Вихід з облікового запису.

Функціональні вимоги описують основні дії, які користувач повинен мати змогу виконати під час роботи із сайтом. Для ApexGaming найважливішими є перегляд товарів, взаємодія з каталогом, використання конструктора ПК, авторизація та робота з профілем. Наявність цих можливостей дозволяє розглядати проєкт не лише як статичну сторінку, а як повноцінний вебзастосунок з інтерактивною логікою.

Окрему роль відіграє кошик, оскільки він поєднує різні сценарії роботи користувача: додавання готового ПК, додавання комплектуючих і збереження сформованої збірки. Завдяки цьому користувач може поступово формувати список потрібних товарів і повертатися до нього під час навігації між сторінками.

### 2.2 Нефункціональні вимоги

До системи висуваються такі нефункціональні вимоги:

1. Адаптивність інтерфейсу для різних розмірів екрана.
2. Зручна навігація між основними сторінками.
3. Швидке завантаження клієнтської частини.
4. Захист паролів за допомогою хешування.
5. Використання токенів доступу для захищених запитів.
6. Можливість локального запуску проекту.
7. Можливість запуску сервісів через Docker Compose.
8. Чітке розділення фронтенду, бекенду та бази даних.

Нефункціональні вимоги визначають якість роботи системи. Для інтернет-магазину важливо, щоб інтерфейс швидко реагував на дії користувача, коректно відображався на різних пристроях і мав зрозумілу структуру. Також важливо, щоб програмний код був поділений на окремі модулі, оскільки це спрощує підтримку та подальше розширення сайту.

Безпека є окремою вимогою, адже сайт працює з даними користувачів. У межах проєкту реалізовано базовий рівень захисту: пароль не зберігається у відкритому вигляді, а для доступу до профілю використовується токен авторизації.

## 3. Програмна частина

У програмній частині описано технології, структуру проєкту та реалізацію основних модулів вебзастосунку. Розділ охоплює клієнтську частину, серверну частину, авторизацію, базу даних і способи запуску системи.

### 3.1 Використані технології

У проекті використано такі технології:

1. React 18 - бібліотека для створення користувацького інтерфейсу.
2. TypeScript - мова програмування з типізацією для фронтенду.
3. Vite - інструмент для швидкої розробки та збірки фронтенду.
4. Tailwind CSS - CSS-фреймворк для стилізації інтерфейсу.
5. Motion - бібліотека для анімацій у React.
6. Lucide React - набір іконок для інтерфейсу.
7. FastAPI - Python-фреймворк для створення серверного API.
8. SQLAlchemy - ORM для взаємодії з базою даних.
9. PostgreSQL - реляційна система керування базами даних.
10. Docker і Docker Compose - інструменти контейнеризації та запуску сервісів.

Вибір цих технологій зумовлений тим, що вони добре підходять для створення сучасного вебзастосунку. React і TypeScript дозволяють будувати компонентний інтерфейс, у якому кожна частина сторінки винесена в окремий компонент. FastAPI забезпечує швидке створення REST API, автоматичну валідацію даних і зручну структуру серверної частини. PostgreSQL використовується як надійна база даних для збереження користувачів та подальшого розширення магазину.

### 3.2 Архітектура проекту

Проект має клієнт-серверну архітектуру. Клієнтська частина відповідає за відображення сторінок, взаємодію з користувачем і надсилання HTTP-запитів до сервера. Серверна частина обробляє запити, виконує авторизацію, працює з базою даних і повертає відповіді у форматі JSON.

Основні частини проекту:

1. `frontend` - клієнтський застосунок на React.
2. `backend` - серверний застосунок на FastAPI.
3. `database` - SQL-схема бази даних.
4. `docker` - Dockerfile для фронтенду та бекенду.
5. `docker-compose.yml` - конфігурація для запуску сервісів.
6. `docs` - документація проекту.

Така структура дає змогу незалежно розвивати окремі частини системи. Наприклад, зовнішній вигляд сайту можна змінювати у папці `frontend`, не змінюючи логіку API. Серверні маршрути можна розширювати у папці `backend`, не впливаючи на верстку сторінок. Конфігурація Docker допомагає запускати базу даних та допоміжні сервіси в однаковому середовищі.

### 3.3 Опис клієнтської частини

Клієнтська частина реалізована як односторінковий застосунок. Основний компонент `App.tsx` керує переходами між сторінками, станом авторизації та збереженням даних користувача у `localStorage`.

Головна сторінка містить такі блоки:

1. Шапку сайту з навігацією.
2. Hero-секцію з візуальною презентацією магазину.
3. Блок популярних продуктів.
4. Блок переваг магазину.
5. Блок індивідуальної збірки.
6. Банер ігрового сетапу.
7. Відгуки користувачів.
8. Підвал сайту.

Для стилізації використовується Tailwind CSS. Анімації реалізовані за допомогою бібліотеки Motion. Іконки підключені через Lucide React. Такий підхід дозволяє створити сучасний, адаптивний і візуально привабливий інтерфейс.

Клієнтська частина також відповідає за збереження частини даних у браузері. Для цього використовується `localStorage`, де можуть зберігатися дані користувача, токен авторизації та вміст кошика. Завдяки цьому після оновлення сторінки користувач не втрачає поточний стан роботи із сайтом.

### 3.4 Опис серверної частини

Серверна частина реалізована за допомогою FastAPI. Вона містить маршрути для авторизації та роботи з даними користувача.

Основні маршрути API:

1. `GET /` - перевірка базової відповіді сервера.
2. `GET /api/health` - перевірка працездатності API.
3. `POST /api/auth/register` - реєстрація користувача.
4. `POST /api/auth/login` - вхід користувача.
5. `GET /api/users/me` - отримання даних поточного користувача.
6. `PATCH /api/users/me/avatar` - оновлення аватара користувача.

Для роботи з базою даних використовується SQLAlchemy. Дані користувача описані через модель `User`, яка містить ідентифікатор, ім'я, email, хеш пароля, аватар і дату створення.

Серверна частина виступає посередником між клієнтським інтерфейсом і базою даних. Вона приймає запити від фронтенду, перевіряє передані дані, виконує необхідні дії та повертає результат у форматі JSON. Такий формат є зручним для вебзастосунків, оскільки легко обробляється у JavaScript/TypeScript.

### 3.5 Авторизація і безпека

У проекті реалізовано базову систему авторизації. Під час реєстрації пароль користувача не зберігається у відкритому вигляді, а перетворюється на хеш. Під час входу система порівнює введений пароль із збереженим хешем.

Після успішної авторизації сервер створює JWT-токен. Клієнтська частина зберігає цей токен у `localStorage` і додає його до захищених запитів у заголовку `Authorization`. На сервері токен перевіряється перед доступом до маршруту профілю.

Такий підхід дозволяє відокремити публічні маршрути від захищених і забезпечити базову перевірку користувача.

### 3.6 База даних

Для збереження даних використовується PostgreSQL. У проекті передбачена таблиця користувачів, а також SQL-схема для потенційного розширення магазину товарами, замовленнями та позиціями замовлень.

Основна сутність користувача містить такі поля:

1. `id` - унікальний ідентифікатор користувача.
2. `name` - ім'я користувача.
3. `email` - електронна пошта.
4. `password_hash` - хеш пароля.
5. `avatar_url` - посилання або дані аватара.
6. `created_at` - дата створення запису.

Використання PostgreSQL є доцільним, оскільки ця система керування базами даних підтримує надійне збереження структурованих даних, індекси, зв'язки між таблицями та масштабування.

### 3.7 Запуск проекту

Для локального запуску фронтенду потрібно перейти до папки `frontend`, встановити залежності та запустити dev-сервер:

```bash
npm install
npm run dev
```

Для запуску бекенду потрібно перейти до папки `backend`, створити віртуальне середовище, встановити залежності та запустити сервер:

```bash
python -m venv venv
.\venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Також проект підтримує запуск через Docker Compose:

```bash
docker-compose up
```

## 4. Експериментальна частина

Експериментальна частина містить перевірку працездатності розробленого програмного продукту. У ній описано способи запуску, збірки та тестової перевірки основних компонентів системи.

### 4.1 Перевірка працездатності

Працездатність клієнтської частини перевіряється командою:

```bash
npm run build
```

Працездатність Python-коду можна перевірити компіляцією модулів:

```bash
python -m compileall app main.py
```

Після запуску сервера додатково можна перевірити API через браузер, Postman або cURL:

```bash
curl http://localhost:8000/api/health
```

Якщо команда збірки завершується без помилок, це означає, що клієнтська частина має коректні імпорти, валідну структуру компонентів і може бути підготовлена до розміщення на хостингу. Перевірка API через `/api/health` дозволяє швидко переконатися, що сервер запущений і відповідає на HTTP-запити.

### Розрахунок собівартості програмного продукту

Собівартість програмного продукту складається з витрат на оплату праці, нарахувань на заробітну плату, витрат на електроенергію, амортизацію обладнання, використання інтернету та інших накладних витрат.

Загальна формула собівартості:

```text
C = ЗП + Нзп + Вел + Вам + Вінт + Внакл
```

де:

- `C` - собівартість програмного продукту;
- `ЗП` - основна заробітна плата розробника;
- `Нзп` - нарахування на заробітну плату;
- `Вел` - витрати на електроенергію;
- `Вам` - амортизація обладнання;
- `Вінт` - витрати на інтернет;
- `Внакл` - інші накладні витрати.

Для розрахунку прийнято такі вихідні дані:

| Показник | Значення |
| --- | ---: |
| Загальна трудомісткість | 150 год |
| Погодинна ставка розробника | 200 грн/год |
| Нарахування на заробітну плату | 22% |
| Потужність робочого місця | 0,35 кВт |
| Тривалість роботи обладнання | 150 год |
| Тариф на електроенергію | 4,32 грн/кВт*год |
| Вартість обладнання | 30000 грн |
| Строк корисного використання обладнання | 36 місяців |
| Тривалість розробки | 1 місяць |
| Інтернет | 300 грн/місяць |
| Інші накладні витрати | 10% від основної зарплати |

Основна заробітна плата:

```text
ЗП = 150 * 200 = 30000 грн
```

Нарахування на заробітну плату:

```text
Нзп = 30000 * 0,22 = 6600 грн
```

Витрати на електроенергію:

```text
Вел = 0,35 * 150 * 4,32 = 226,80 грн
```

Амортизація обладнання за один місяць:


Інші накладні витрати:

Економічна ефективність впровадження сайту полягає в автоматизації презентації товарів, зменшенні часу на консультації клієнтів, підвищенні зручності вибору ПК та можливості приймати заявки або замовлення онлайн.

| Показник | Значення |

Чистий місячний економічний ефект:

```text
Еміс = 20000 - 3000 = 17000 грн
```

Річний економічний ефект:

```text
Еріч = 17000 * 12 = 204000 грн
```

Коефіцієнт економічної ефективності визначається як відношення річного економічного ефекту до капітальних вкладень:

```text
Кеф = Еріч / К
```

де:

- `Кеф` - коефіцієнт економічної ефективності;
- `Еріч` - річний економічний ефект;
- `К` - капітальні вкладення, тобто ціна створення програмного продукту.

Для розрахунку приймаємо капітальні вкладення на рівні ціни без ПДВ:

```text
Кеф = 204000 / 51200,16 = 3,98
```

Отримане значення показує, що протягом року очікуваний економічний ефект може майже в 4 рази перевищити витрати на створення сайту.
