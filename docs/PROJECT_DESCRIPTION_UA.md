# Опис вебсайту ApexGaming

## Вступ

ApexGaming - це вебсайт інтернет-магазину ігрових комп'ютерів, комплектуючих та індивідуальних ПК-збірок. Проєкт орієнтований на користувачів, які хочуть швидко переглянути готові ігрові системи, підібрати комплектуючі, зібрати власну конфігурацію ПК, додати товари до кошика та користуватися особистим профілем.

Сайт має клієнт-серверну архітектуру. Клієнтська частина відповідає за інтерфейс, навігацію, каталог, кошик, конструктор ПК та взаємодію з користувачем. Серверна частина реалізує API для авторизації, реєстрації та роботи з даними профілю. Для збереження даних використовується база даних PostgreSQL.

Метою створення проєкту є розробка сучасного вебзастосунку для демонстрації основних можливостей інтернет-магазину комп'ютерної техніки: презентації товарів, роботи з кошиком, авторизації користувача, збереження профілю та підготовки системи до локального запуску або розгортання.

## 1. Теоретична частина

Інтернет-магазин є одним із найпоширеніших типів вебзастосунків, оскільки він дає змогу користувачам переглядати товари, порівнювати характеристики та виконувати дії без відвідування фізичної точки продажу. У випадку магазину ігрових комп'ютерів важливими є не лише ціна та назва товару, а й технічні характеристики, візуальна подача, зрозуміла структура каталогу та можливість конфігурування системи під власні потреби.

Предметна область проєкту охоплює продаж готових ПК, комплектуючих і створення індивідуальних збірок. Користувачу потрібно мати можливість переглядати головну сторінку, переходити до каталогу, відкривати сторінку комплектуючих, користуватися конструктором ПК, додавати позиції до кошика та керувати обліковим записом.

Для побудови такого сайту доцільно використовувати клієнт-серверну модель. Клієнтська частина працює у браузері та забезпечує швидкий, інтерактивний інтерфейс. Серверна частина приймає HTTP-запити, перевіряє дані, виконує авторизацію і взаємодіє з базою даних. Такий підхід дає змогу розділити відповідальність між інтерфейсом і бізнес-логікою.

У проєкті використано такі основні технології:

1. React - бібліотека для створення компонентного користувацького інтерфейсу.
2. TypeScript - мова програмування з типізацією для зменшення кількості помилок у фронтенді.
3. Vite - інструмент для швидкої розробки та збірки клієнтської частини.
4. Tailwind CSS - CSS-фреймворк для створення адаптивного дизайну.
5. FastAPI - Python-фреймворк для реалізації серверного API.
6. SQLAlchemy - ORM для роботи з базою даних.
7. PostgreSQL - реляційна система керування базами даних.
8. Docker Compose - засіб для запуску декількох сервісів проєкту.

Основними вимогами до сайту є зручна навігація, адаптивний дизайн, зрозумілий каталог, наявність кошика, можливість авторизації, базовий захист паролів, швидке завантаження сторінок і можливість подальшого розширення функціональності.

## 2. Конструкторська частина

Під час проєктування сайту ApexGaming було визначено основні сторінки та функціональні блоки, які формують користувацький сценарій. Структура інтерфейсу побудована так, щоб користувач міг швидко перейти від ознайомлення з магазином до вибору товару або створення власної збірки.

Основні сторінки сайту:

1. Головна сторінка - презентація магазину, популярних товарів, переваг, індивідуальних збірок, відгуків і банерів.
2. Каталог - перегляд готових ігрових комп'ютерів.
3. Сторінка комплектуючих - вибір окремих компонентів для ПК.
4. Конструктор ПК - підбір комплектуючих для формування власної конфігурації.
5. Кошик - перегляд доданих товарів, збірок і комплектуючих.
6. Сторінка авторизації - реєстрація та вхід користувача.
7. Профіль - перегляд даних користувача, оновлення аватара та робота з власними збірками.
8. Сторінка "Про нас" - інформація про магазин, переваги та навігаційні секції.

Інтерфейс сайту спроєктований як односторінковий застосунок. Перехід між сторінками відбувається без повного перезавантаження браузера, що робить взаємодію швидшою та комфортнішою. Основний компонент застосунку керує поточною сторінкою, станом користувача, кошиком і переходами між розділами.

У конструкторській частині передбачено такі логічні модулі:

1. Навігаційна панель із переходами до основних сторінок.
2. Hero-секція для першого враження та переходу до каталогу.
3. Каталог готових ПК з можливістю додавання товару до кошика.
4. Блок комплектуючих із додаванням окремих компонентів.
5. Конструктор ПК для підбору сумісних частин.
6. Кошик із підрахунком доданих позицій.
7. Авторизація та профіль користувача.
8. Підвал сайту з додатковою навігацією.

Дані кошика та користувача частково зберігаються у браузері за допомогою `localStorage`. Це дає змогу не втрачати стан під час переходів між сторінками або після оновлення браузера. Для авторизованого користувача також використовується токен доступу, який додається до захищених запитів.

Візуальна концепція сайту відповідає тематиці ігрової техніки: використано контрастні блоки, великі зображення комп'ютерів, акцентні кнопки, картки товарів, анімації та сучасну структуру сторінок. Дизайн адаптований для перегляду на різних екранах.

## 3. Програмна частина

Програмна реалізація проєкту поділена на фронтенд, бекенд, базу даних і конфігураційні файли для запуску.

Клієнтська частина розташована у папці `frontend`. Вона реалізована на React із використанням TypeScript. Основний файл `App.tsx` керує сторінками, станом авторизації, кошиком і передає потрібні функції до дочірніх компонентів. Компоненти інтерфейсу винесені в окремі файли: `Header`, `Footer`, `HeroSection`, `CatalogPage`, `ComponentsPage`, `PcBuilderPage`, `CartPage`, `AuthPage`, `ProfilePage`, `AboutPage` та інші.

Основні функції фронтенду:

1. Відображення головної сторінки та інформаційних блоків.
2. Перехід між сторінками без повного перезавантаження.
3. Відображення каталогу готових ПК.
4. Відображення комплектуючих.
5. Формування користувацької ПК-збірки.
6. Додавання товарів, комплектуючих і збірок до кошика.
7. Збереження кошика у локальному сховищі браузера.
8. Реєстрація та авторизація через API.
9. Збереження токена та даних користувача.
10. Оновлення профілю користувача.

Серверна частина розташована у папці `backend`. Вона реалізована на FastAPI. Файл `main.py` створює застосунок, підключає CORS, маршрути авторизації та маршрути користувача. Окремі модулі відповідають за моделі, схеми даних, роботу з базою, безпеку та залежності.

Основні API-маршрути:

1. `GET /` - базова перевірка роботи сервера.
2. `GET /api/health` - перевірка стану API.
3. `POST /api/auth/register` - реєстрація користувача.
4. `POST /api/auth/login` - авторизація користувача.
5. `GET /api/users/me` - отримання даних поточного користувача.
6. `PATCH /api/users/me/avatar` - оновлення аватара користувача.

Для захисту паролів використовується хешування. Після успішного входу сервер створює JWT-токен, який клієнтська частина зберігає у браузері. Під час звернення до захищених маршрутів токен передається в заголовку `Authorization`.

База даних PostgreSQL використовується для збереження користувачів та може бути розширена для товарів, замовлень і позицій замовлень. У проєкті також є файл `database/schema.sql`, який описує структуру таблиць для подальшого розвитку системи.

Для запуску середовища використовується `docker-compose.yml`, який містить сервіси PostgreSQL, pgAdmin, бекенду та фронтенду. Також створено PowerShell-скрипти `start.ps1` і `stop.ps1`, які спрощують локальний запуск і зупинку проєкту.

## 4. Експериментальна частина

Експериментальна частина передбачала перевірку працездатності основних функцій сайту та стабільності збірки. Основну увагу було приділено тому, щоб застосунок запускався локально, коректно збирався для production-режиму та мав робочі сценарії взаємодії користувача.

Перевірялися такі сценарії:

1. Запуск клієнтської частини за допомогою `npm run dev`.
2. Збірка фронтенду командою `npm run build`.
3. Запуск серверної частини через `python main.py`.
4. Перевірка API-маршруту `GET /api/health`.
5. Перехід між головною сторінкою, каталогом, комплектуючими, конструктором, кошиком і профілем.
6. Додавання готового ПК до кошика.
7. Додавання комплектуючих до кошика.
8. Формування збірки у конструкторі.
9. Збереження кошика у браузері.
10. Реєстрація та вхід користувача.
11. Перевірка роботи профілю та оновлення аватара.

Під час перевірки фронтенд успішно зібрався у production-режимі. Це підтверджує, що TypeScript-код, імпорти компонентів, стилі та статичні ресурси підключені коректно. Сайт також підготовлений до розгортання з гілки `master`, оскільки останні зміни було змержено та запушено до віддаленого репозиторію.

У результаті експериментальної перевірки підтверджено, що основні сторінки сайту працюють, навігація виконується без перезавантаження, кошик зберігає товари, а серверна частина має базові маршрути для авторизації та профілю.

## Висновки

У результаті виконання роботи було створено вебсайт ApexGaming - інтернет-магазин ігрових комп'ютерів, комплектуючих та індивідуальних збірок. Проєкт має сучасний інтерфейс, модульну структуру, клієнт-серверну архітектуру та підготовлене середовище для локального запуску.

Під час розробки було реалізовано головну сторінку, каталог, сторінку комплектуючих, конструктор ПК, кошик, сторінку авторизації, профіль користувача та інформаційну сторінку про магазин. Фронтенд створено на React і TypeScript, бекенд - на FastAPI, а для збереження даних використано PostgreSQL.

Розроблений сайт демонструє практичне застосування сучасних технологій веброзробки. Його можна використовувати як основу для подальшого розвитку повноцінної платформи електронної комерції. У майбутньому систему можна розширити адміністративною панеллю, оплатою, оформленням замовлень, історією покупок, фільтрами каталогу та повним керуванням товарами з бази даних.
